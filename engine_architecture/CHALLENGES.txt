
ENGINE IMPLEMENTATION CHALLENGES — INDEX
========================================
Build order designed so each phase produces something runnable, and nothing you
build gets thrown away in a later phase. This file is the index; each phase is a
separate, detailed file under challenges/ (read the whole phase file before
starting it).

The renderer is cgfx (a standalone C23 WebGPU library, consumed as a submodule).
Read the companion design docs before Phase 0:
  ARCHITECTURE.txt         the map (ownership, tick, components, layout)
  FOUNDATIONS.txt          repo/build, the C23<->C++20 boundary, cglm landmine
  RENDER_INTEGRATION.txt   driving cgfx, materials, WGSL contract, coordinates
  SCENE.txt                the scene system, lifecycle, transform fixes

Legend (used inside each phase file):
  [ ] task to implement (broken into lettered micro-steps, e.g. 4.2.a)
  [M] milestone — the engine can do this when the phase is done
  [!] common mistake / thing to watch out for
  Each phase also has: WHY THIS PHASE, CONCEPTS YOU NEED (plain-language primers
  with worked examples), "How to know it works" checks, and WHAT FAILURE LOOKS LIKE.

WHAT COMES AFTER (not yet — earn it first; each assumes Phase 10 is solid)
-------------------------------------------------------------------------------

  Editor           separate target linking the same engine lib; uses ecs() to
                   enumerate/modify; Phase 10 serialization saves scenes.
  Shadows / passes cgfx ALREADY has MRT, MSAA, offscreen targets, multi-pass
                   frames (begin_render_pass_ex + Comparison samplers). CastsShadow
                   exists. A shadow pass is incremental, not a rewrite
                   (RENDER_INTEGRATION 7).
  Async assets     job queue + refcounting in front of AssetManager.
  Animation        Skeleton + AnimationClip + AnimatorSystem after TransformSystem,
                   overriding bone WorldTransforms. @group(3) is reserved for the
                   bone palette; CgfxVertex already carries joints/weights.
  Collision events Jolt ContactListener -> per-frame event buffer -> a flecs system
                   fires observers.
  Prefab tooling   authoring/editing prefabs in the editor (runtime instancing
                   already exists from Phase 6.5).
