
ENGINE ARCHITECTURE — CLASS CONNECTIONS & DATA FLOW
=====================================================

OWNERSHIP (Engine owns these as members)
─────────────────────────────────────────────────────────────────────────────

  Engine
  ├── flecs::world          (ECS — entity/component storage)
  ├── AssetManager          (mesh + material GPU handles)
  ├── InputSystem           (platform events → ECS)
  ├── PhysicsBridge         (Jolt simulation ↔ ECS)
  └── RenderBridge          (ECS → C renderer)


FRAME TICK — Engine::tick(dt, aspect)
─────────────────────────────────────────────────────────────────────────────

  Platform loop
       │
       ▼
  Engine::tick()
       │
       ├─[1]─► InputSystem::poll_and_write(world, player_entity)
       │             │
       │        reads OS events (keyboard, mouse)
       │             │
       │        world.entity(player).set<InputState>({ move, look, jump... })
       │                                        │
       │                              written to ECS ──────────────────────┐
       │                                                                   │
       ├─[2]─► PhysicsBridge::step_and_writeback(world, dt)               │
       │             │                                                     │
       │        reads <InputState> from ECS ◄──────────────────────────── ┘
       │             │
       │        push velocity/forces into Jolt bodies
       │             │
       │        JoltPhysicsSystem::Update(dt)    ← pure simulation
       │             │
       │        for each (BodyID → entity) mapping:
       │             world.entity(e).set<Position>(jolt_pos)
       │                            .set<Rotation>(jolt_rot)
       │                                        │
       │                              written to ECS ──────────────────────┐
       │                                                                   │
       ├─[3]─► world.progress(dt)   (Flecs runs registered systems)       │
       │             │                                                     │
       │        ┌────┴────────────────────────────────────────────────┐    │
       │        │  Flecs system scheduler                              │    │
       │        │                                                      │    │
       │        │  [3a] Transform_Roots  (no parent)                  │    │
       │        │         reads  <Position, Rotation, Scale> ◄──────── ┘   │
       │        │         writes <WorldTransform>                     │    │
       │        │                      │                              │    │
       │        │  [3b] Transform_Children  (.after 3a)              │    │
       │        │         reads  <Position, Rotation, Scale>          │    │
       │        │         reads  parent<WorldTransform>               │    │
       │        │         writes <WorldTransform>  (parent * local)   │    │
       │        │                      │                              │    │
       │        │  [3c] CameraSystem   (.after 3b)                   │    │
       │        │         reads  <WorldTransform>  (IsCamera entity)  │    │
       │        │         writes <CameraData> { view, proj, pos }     │    │
       │        │                                                      │    │
       │        └──────────────────────────────────────────────────── ┘    │
       │                                                                   │
       │                         all WorldTransforms now fresh ────────── ┐│
       │                         CameraData now fresh ─────────────────── ┤│
       │                                                                  ││
       └─[4]─► RenderBridge::submit_frame(world, aspect)                 ││
                     │                                                    ││
                reads <CameraData>    from ECS ◄──────────────────────── ┘│
                reads <WorldTransform>                                      │
                reads <MeshHandle>    } per renderable entity ◄──────────── ┘
                reads <MaterialHandle>}
                reads <CastsShadow>   tag (optional)
                     │
                resolves handles via AssetManager
                     │
                builds FrameDrawList { DrawCall[], view[], proj[] }
                     │
                ─────┼──── ECS boundary — renderer never crosses this ────
                     │
                renderer_begin_frame()
                renderer_set_camera(view, proj, pos)
                for each DrawCall:
                    renderer_submit_mesh(mesh_id, mat_id, world_matrix)
                renderer_end_frame()


COMPONENT DATA FLOW (who writes, who reads)
─────────────────────────────────────────────────────────────────────────────

  Component          Written by              Read by
  ─────────────────  ──────────────────────  ─────────────────────────────
  Position           PhysicsBridge           TransformSystem (both passes)
  Rotation           PhysicsBridge           TransformSystem (both passes)
  Scale              (user / scene setup)    TransformSystem (both passes)
  WorldTransform     TransformSystem         CameraSystem, RenderBridge
  InputState         InputSystem             PhysicsBridge, gameplay systems
  CameraData         CameraSystem            RenderBridge
  MeshHandle         (scene setup)           RenderBridge
  MaterialHandle     (scene setup)           RenderBridge
  PhysicsBodyID      PhysicsBridge (init)    PhysicsBridge (internal map)

  Tag components: IsCamera, IsStatic, CastsShadow
    — written at entity creation, used as query filters only


CLASS DECISION RATIONALE
─────────────────────────────────────────────────────────────────────────────

  CLASS (owns resources, has init/shutdown lifecycle)
  ├── Engine          — owns all subsystems
  ├── AssetManager   — owns GPU resource arrays + cache maps
  ├── InputSystem    — owns bitset state across frames
  ├── PhysicsBridge  — owns Jolt PhysicsSystem, allocators, body map
  └── RenderBridge   — owns draw list buffer, pointer to C renderer state

  NAMESPACE of FREE FUNCTIONS (pure logic, no persistent state)
  ├── TransformSystem::build_trs()         — pure math
  ├── TransformSystem::register_systems()  — one-time setup, no state
  └── CameraSystem::compute_view/proj()    — pure math
      CameraSystem::register_systems()     — one-time setup, no state

  STRUCTS (plain data, no methods, Flecs owns them)
  └── All components in components.hpp


STATIC LIBRARY PUBLIC SURFACE (what game/editor code sees)
─────────────────────────────────────────────────────────────────────────────

  engine/core/engine.hpp       — Engine, EngineConfig
  engine/core/entity_id.hpp    — EntityID (opaque handle)
  engine/systems/input_system.hpp  — Key, MouseButton (for input queries)

  Everything else is an implementation detail.
  Consumers never include: flecs.h, cglm.h, Jolt/*.h


SCENE GRAPH (Flecs ChildOf relationship)
─────────────────────────────────────────────────────────────────────────────

  world                          (flecs::world)
  └── vehicle  (root entity)
        ├── body   (ChildOf vehicle)
        │     ├── wheel_fl  (ChildOf body)
        │     └── wheel_fr  (ChildOf body)
        └── turret (ChildOf vehicle)
              └── barrel  (ChildOf turret)

  Transform_Roots  processes: vehicle
  Transform_Children processes: body, turret, wheel_fl, wheel_fr, barrel
  (Flecs guarantees parents before children within pass 2)

  INCLUDE DEPENDENCY RULES (enforced by directory structure)
  ───────────────────────────────────────────────────────────

  core/        → no includes from other engine/ dirs (foundational)
  assets/      → may include core/
  systems/     → may include core/  (reads/writes components)
  physics/     → may include core/  (reads/writes components)
  render/      → may include core/, assets/
  engine.hpp   → includes all of the above (it's the wiring layer)

  third_party/ headers stay INSIDE their subsystem:
    Jolt/*.h   → only in physics/
    flecs.h    → only in core/engine.hpp and systems/ (never in components.hpp)
    cglm/      → in core/components.hpp (vec3/mat4 are component types)
                 and renderer/ (already there)

  The goal: nothing in examples/ or a future editor/ needs to know
  what physics library or ECS you use. They include engine.hpp and stop.


  CMAKE SKETCH
  ───────────────────────────────────────────────────────────

  # root CMakeLists.txt
  cmake_minimum_required(VERSION 3.22)
  project(myengine)
  set(CMAKE_CXX_STANDARD 20)

  add_subdirectory(third_party/flecs)
  add_subdirectory(third_party/JoltPhysics)
  add_subdirectory(renderer)      # → target: renderer
  add_subdirectory(engine)        # → target: engine  (links renderer, flecs, Jolt)
  add_subdirectory(examples)      # → target: sandbox (links engine)
  add_subdirectory(tests)         # → target: engine_tests

  # engine/CMakeLists.txt
  add_library(engine STATIC
      core/engine.cpp
      assets/asset_manager.cpp
      systems/transform_system.cpp
      systems/camera_system.cpp
      systems/input_system.cpp
      physics/physics_bridge.cpp
      render/render_bridge.cpp
  )
  target_include_directories(engine PUBLIC .)   # consumers: #include "engine/core/engine.hpp"
  target_link_libraries(engine PRIVATE renderer flecs Jolt)
